# Kaggriculture

Read [goal.md](goal.md) first — it defines the improve → gate → submit → learn loop and
what may be submitted. [AGENTS.md](AGENTS.md) has the agent API, engine setup and every
Kaggle CLI command. [README.md](README.md) has the full game rules and price tables.
[lab/loop_journal.md](lab/loop_journal.md) is the running history — append, never rewrite.

## Setup

```bash
pip install -r requirements.txt
```

On a Debian-based cloud image `pip` may refuse with `Cannot uninstall blinker ... RECORD file
not found` (a distro-installed package). Add `--ignore-installed blinker`:

```bash
pip install --ignore-installed blinker -r requirements.txt
```

The ledger's `artifacts.path` column holds absolute Windows paths from the original machine.
`lab.ledger.artifact_path()` falls back to the tracked, content-addressed copy at
`lab/artifacts/<sha8>/main.py`, so gates and tournaments resolve artifacts by name on any OS.

`KAGGLE_API_TOKEN` must be in the environment for anything that talks to Kaggle (submit,
sync, episodes, replay, leaderboard). Locally it is read from `kaggle.json`; in a cloud
agent set it as a secret. Everything else — tournaments, gates, replay analysis — runs
without it.

## What a fresh checkout does not have

Gitignored:

- `lab/replays/`, `lab/ladder_replays/`, `lab/top_replays/` — ~5 GB of `.json.gz`
  episodes. Ladder replays come back with
  `kaggle competitions replay <EPISODE_ID> -p lab/ladder_replays/<sub_id>`; local ones
  are regenerated by running the tournament.
- `lab/p2/data/*.npz` — behaviour-cloning datasets; regenerate with `python -m lab.p2.collect`.
- `*.log` / `*.err` — gate and run logs. The tracked `.md` files in `lab/reports/` are the
  durable record.

`lab/runs.db` (artifacts, batches, games, submissions) and the Phase-2 `.pt` models *are*
tracked. `runs.db` is binary and cannot be merged — one writer at a time, and pull before
starting an iteration.

## Hard rules

- Nothing is submitted that has not passed `python -m lab.gate`. VETO means stop.
- 5 Kaggle submissions per UTC day; only the latest 2 stay active.
- Claude submits gated candidates itself — see goal.md step 6.
- Every run lands in `lab/runs.db`, losses included.
